# 핵심 네 사례 시연 스토리 — 원문 확인 반영

전체 상태: 정적 설명 초안. 최신 Live·V6·QA 전체 성공을 주장하지 않는다.

## C001: 문서와 계산의 역할 분리
PDF 본문과 기존 검수표 흔적, 보관 V4 추출·계산 파일을 확보했다. 보관 analysis.json의 부족 0→60과 예상 비용 60500.00을 보관 결과라고 명시한다. 기존 사람 검수를 다시 수행하도록 요구하지 않으며 XLSX 셀별 승인 범위는 판독 경로 오류로 확인 대기다. 세 PDF 단일 운영 Job·최신 V6·QA·Gold 연결은 미검증.

## C013: 식별자 보존
이제 목표만이 아니라 실제 첨부 PDF의 차이를 보여줄 수 있다. 발주서 1쪽 PO ID는 PO1, 견적서 1쪽 Related PO는 PO1, 변경통보 1쪽 PO ID는 PO999다. 세 문서의 해당 행을 나란히 제시하고 '원문 식별자가 충돌하므로 자동 연결하지 않아야 한다'고 설명한다. 실제 차단 결과 화면은 아직 없으므로 '차단 성공했다'고 말하지 않는다. PO의 O를 숫자 0으로 바꾸지 않는다.

## C008: 변경 범위 보존
발주서 1쪽 품목 표 R1 40 EA와 R2 60 EA를 먼저 보여주고, 변경통보 1쪽의 R2 60 EA 및 '다른 입고는 기존 날짜 유지' 문구로 이동한다. '변경 대상은 R2이며 R1까지 이동시키면 안 된다'는 문서 사실·요구 동작을 설명한다. 공급 가능량 60 EA는 견적의 용량이며 실제 구매량이 아니다. 엔진의 중복 배분 방지나 최종 부족·비용은 실제 실행 자료를 받은 후 추가한다.

## C017: 원문과 정규화 구분
발주서 Original delivery '2026년 11월 3일', 통보서 Revised delivery '2026년 11월 8일', 견적서 Arrival date '2026년 11월 4일'을 보여준다. 각각의 의미에 맞는 ISO 후보 2026-11-03/08/04를 설명하되, 프로그램의 실제 정규화 성공과 구분한다. 날짜 역할을 섞지 않는다.

## 촬영·발표 제한
세 보조 사례 원문 확보 9/9 및 핵심 본문 대조 완료. PDF는 합성 DRAFT 자료이며 사람 승인본·실거래 자료로 소개하지 않는다. 견적은 구매 미실행 상태다. 화면에서 PDF를 여는 것은 신규 Job 실행이 아니다. 실제 QA·V6 출력이 없으면 기대 동작과 문서 사실만 설명한다.
